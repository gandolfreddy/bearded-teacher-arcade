# 需求、架構與驗收計畫

日期：2026-11-03；規劃版本：v0.1；狀態：T01／T02 已實作並完成本輪限定驗收；正式遊戲已實作、本機整合通過；平板實機及最新部署待驗。

## 一、來源與邊界

使用者明確要求：GitHub Pages 小遊戲集合網站、電腦／平板鍵盤／觸控操作、index.html 搭配各 HTML 遊戲、SPA 風格切換、遊戲 HTML 統一 games/ 管理、命名包含大鬍子＋老師＋遊戲廣場概念。
使用者要求依前次建議開始規劃。以下任務、視覺與首批遊戲是具體提案，並非全部已由使用者逐項確認。本次交付規劃文件，不包含建立遠端儲存庫、實作遊戲、發布或宣稱平板驗收通過。
採完整開發流程的需求、分析、設計及任務拆分階段。僅規劃，不虛報 Implement／Deploy 完成。

## 二、需求與可驗收條件

| 代號 | 需求 | 驗收條件 |
|---|---|---|
| R01 | 遊戲 HTML 統一管理 | 所有遊戲入口位於 games/；清單只接受該路徑下明確列出的 HTML |
| R02 | SPA 風格體驗 | 遊戲切換時 index 外框保留；同時最多存在一個作用中的遊戲 iframe |
| R03 | 可分享與返回 | #game=<id> 可直接進遊戲；重整、上一頁、下一頁正確還原；回大廳移除遊戲 |
| R04 | 電腦鍵盤 | 每款首發遊戲有可操作的鍵盤模式；方向鍵只在遊戲操作範圍抑制捲動；失焦清除按住狀態 |
| R05 | 平板觸控 | 首發遊戲均有觸控模式；不靠 hover 顯示必要功能；多指、拖出按鈕、pointercancel 不造成卡鍵 |
| R06 | 遊戲生命週期 | 離開時卸載；背景／失焦時暫停並提供明確恢復；切換後無舊遊戲聲音或持續分數／計時 |
| R07 | 適應畫面 | 1280×720、1024×768、768×1024 CSS 像素無主要功能遮蔽；橫直向切換後可操作 |
| R08 | 可擴充清單 | 新增清單項目及遊戲檔即可收錄；不為每款遊戲修改 app.mjs；錯誤清單不造成整站空白 |
| R09 | 靜態部署 | 以 /<repo>/ 子路徑驗證所有檔案、分享連結及直接遊戲網址；無伺服器執行階段依賴 |
| R10 | 操作與可及性 | 卡片、返回與重玩可用鍵盤操作；焦點清楚；iframe 有 title；觸控主要按鈕目標至少 44×44 CSS 像素 |

44×44 為本案設計目標，不宣稱只通過此尺寸即符合完整無障礙標準。

## 三、第一版範圍

第一版：遊戲卡片、名稱搜尋、操作方式標示、遊戲說明、開始／返回大廳／重玩、遊戲載入與錯誤狀態、兩款遊戲。
提議首批：貪食蛇（方向鍵／WASD＋觸控方向鍵）及翻牌配對（方向鍵選牌＋Enter／Space、觸控點牌）。兩款皆需鍵盤與觸控驗收；題材尚未選定，可在不改架構下替換。
後續：分類篩選、收藏、最近遊玩、本機最佳成績、統一靜音與全螢幕（先驗各目標瀏覽器）。
帳號、全球排行榜、跨裝置存檔、多人連線及離線 PWA 列為後續獨立需求，第一版不引入其服務依賴。

## 四、互動與視覺提案

大廳頂部顯示「大鬍子老師遊戲廣場」與搜尋欄，下方以卡片呈現縮圖、名稱、簡短說明、鍵盤／觸控標示與開始按鈕。遊戲模式縮減外框，保留返回、遊戲名、操作說明與重玩，讓遊戲區盡量大。桌機可用側欄，平板採可收合說明，觸控控制放在不遮擋遊戲的位置。
視覺提案：簡潔的大鬍子老師識別、溫暖底色、深色文字、少量活潑強調色。品牌是遊戲廣場，不自動推定僅供兒童或每款遊戲都須有教學評量。
字型、色票與圖像尚未定案，不繼承 Notes 本機 Dashboard 的專屬外觀偏好。

## 五、架構決策

- 原生 HTML／CSS／JavaScript，先不引入前端框架或建置依賴。JSON 是內容清單，並非資料庫。
- index.html 為網站外框；app.mjs 讀清單、渲染卡片、處理 hash 路由與 iframe 生命週期。
- 使用 #game=<id>，空 hash 表示大廳；未知 id 顯示可返回大廳的錯誤，不猜檔案路徑。
- 路由只接收 id，再查清單取得檔案；不把網址提供的任意字串直接作為 iframe.src。
- 遊戲使用同源 iframe，隔離文件樣式與一般全域變數；不把它當成可執行不可信程式碼的安全沙箱。第三方遊戲須確認授權並覆核來源。
- 先移除舊 iframe，再載入新遊戲；返回或重玩沿用相同流程。同時只載入一款，避免數量增加直接擴大執行成本。
- 用相對路徑，根清單項目以 ./games/ 開頭；遊戲本身的素材相對 games/ 定位。用 HTTP 伺服器預覽，file:// 不是支援的驗收入口。
- 前景／背景處理由各遊戲監聽 visibilitychange／blur；父頁也可送 pause。恢復需玩家明確動作，避免返回頁面立刻開始。
- 獨立開啟 games/<id>.html 也要可玩，父頁通訊不是基本遊戲運作的必要條件。
- iframe load 不代表遊戲成功；透過 ready 訊息、error 與逾時處理顯示狀態。載入逾時暫定 10 秒，可重試；不把它宣稱為瀏覽器可靠的網路錯誤偵測。
- 若後續儲存成績，使用 bta:<game-id>:<schema-version> 命名，處理儲存遭拒或空間不足；本機成績不當作防作弊依據。

## 七、驗證策略與交付階段

第一階段 v0.1.0：網站外框與切換骨架；以測試頁驗證生命週期，測試頁不當正式遊戲交付。
第二階段 v0.2.0：兩款可玩遊戲、說明及鍵盤／觸控整合。
第三階段 v1.0.0：完成目標裝置驗收、部署與回歸後才標正式版本；v0.1.0 已於 2026-11-03 實作並驗證；後續版本仍為目標。

靜態檢查：JSON 格式、id 唯一性、清單路徑限制及檔案存在、部署子路徑資源。
瀏覽器行為：路由重整與前進／返回、連續切換 20 次、舊 iframe 消失且無殘留聲音、重玩、載入失敗、焦點進出、背景暫停與手動恢復。
操作：方向鍵／WASD／Enter／Space；觸控長按與多指、取消、拖出範圍；縮放與方向切換後座標正確；觸控區外仍能正常閱讀捲動。
環境：Windows Chrome／Edge，iPadOS Safari 或 Android Chrome 平板實機。實際使用者平板型號未提供；實作期間先做模擬視窗及可用裝置測試，模擬觸控不等於平板實機通過。
音訊：經玩家動作才啟動，返回大廳停止；若遊戲無音訊則該款註記不適用。
效能：僅載入目前遊戲，縮圖控制大小；記錄實際裝置、載入時間與遊玩流暢度，不在未量測前承諾固定 FPS。

證據需包含提交／檔案雜湊、環境、案例、預期與實際、通過／失敗／未測；每次影響行為的修改需重驗相關項目。發布前保留已驗提交，更新失敗可重新部署前一版本；資料格式變更另處理，不用程式回退推定資料已復原。
